# Менеджер паролей

Лабораторная работа 1, курс Python 2026, тема **Б1 «Менеджер паролей»** (трек DevOps).

Консольное приложение для хранения паролей. Вход по мастер-паролю, записи (сервис, логин, пароль)
хранятся в файле `vault.json`, пароли в нём зашифрованы.

## Возможности

- создание хранилища с мастер-паролем (`--init`), повторное создание запрещено;
- вход по мастер-паролю (`--unlock`) со скрытым вводом через `getpass`;
- меню: добавить, список, показать пароль, удалить запись, сгенерировать пароль;
- показ пароля только после повторного ввода мастер-пароля;
- в списке выводятся только названия, без паролей;
- генератор надёжных паролей (`--generate`): строчные и заглавные буквы, цифры и спецсимволы гарантированно;
- понятные сообщения об ошибках вместо трейсбеков.

## Как устроена безопасность

```
SHA-256(auth_salt + мастер-пароль) → verifier  — хранится в файле, проверяет вход
SHA-256(enc_salt  + мастер-пароль) → ключ      — только в памяти, нигде не сохраняется
Fernet(ключ, пароль записи)        → токен     — хранится в файле
```

- **Мастер-пароль не хранится.** В файле только его хэш SHA-256 со случайной солью (`os.urandom`).
  При входе хэш считается заново и сравнивается через `hmac.compare_digest` (защита от timing-атак).
- **Пароли записей зашифрованы** алгоритмом Fernet из библиотеки `cryptography` (AES-128-CBC + HMAC-SHA256).
  Fernet при каждом шифровании добавляет случайный IV, поэтому одинаковые пароли дают разные токены.
- **Ключ шифрования не хранится.** Он выводится из мастер-пароля с отдельной солью при каждом входе
  и стирается из памяти при выходе. Соли разные, поэтому ключ не совпадает с хэшем из файла.
- **Запись файла атомарная:** данные пишутся во временный файл и подменяют основной одной операцией,
  поэтому сбой при сохранении не повредит хранилище.
- Генератор паролей использует модуль `secrets`, а не предсказуемый `random`.

## Установка

Нужен Python 3.11+ и [uv](https://docs.astral.sh/uv/).

```bash
uv sync
```

## Запуск

```bash
uv run pm --init                  # создать хранилище и мастер-пароль
uv run pm --unlock                # войти, дальше меню
uv run pm --generate              # сгенерировать пароль (16 символов)
uv run pm --generate --length 24  # своей длины (минимум 8)
uv run pm --unlock --vault my.json  # другой файл хранилища
uv run pm --help                  # справка
```

Меню после входа:

```
1. Добавить запись
2. Список записей
3. Показать пароль
4. Удалить запись
5. Сгенерировать пароль
0. Выход
```

Запускайте из обычного терминала: в консоли Run в PyCharm скрытый ввод `getpass` работает некорректно.

## Структура проекта

```
src/password_manager/
  __init__.py   пакет
  crypto.py     соль, хэш мастер-пароля, ключ, шифрование и расшифровка (Fernet)
  storage.py    чтение и атомарная запись vault.json
  manager.py    класс PasswordManager — вся логика, без ввода-вывода
  gen_pas.py    генератор надёжных паролей
  cli.py        argparse, getpass, меню, обработка ошибок
tests/
  test_manager.py   тесты pytest
.github/workflows/ci.yml   проверки в GitHub Actions
pyproject.toml             зависимости и настройки ruff, mypy, pytest
```

Логика (`manager.py`) отделена от интерфейса (`cli.py`): менеджер ничего не печатает и не читает с клавиатуры,
а только выполняет операции и выбрасывает исключения. Поэтому его можно полностью проверить тестами.

## Формат vault.json

```json
{
  "auth_salt": "…base64…",
  "verifier": "…base64…",
  "enc_salt": "…base64…",
  "entries": {
    "github": {"login": "user", "password": "gAAAAAB…"}
  }
}
```

## Проверки

```bash
uv run pytest                    # тесты
uv run ruff check .              # линтер
uv run ruff format --check .     # форматирование
uv run mypy --strict src tests   # строгая проверка типов
```

Тесты проверяют:

- `unlock` с верным паролем → `True`, с неверным → `False`;
- повторный `init` запрещён;
- `add` → `list` показывает имя, `get` возвращает пароль;
- `delete` удаляет запись;
- в файле нет мастер-пароля и паролей записей в открытом виде;
- после `lock` работа с записями запрещена;
- разные соли дают разные хэши;
- генератор выдаёт пароль нужной длины со всеми типами символов и отклоняет слишком короткую длину.

Все проверки запускаются в GitHub Actions при каждом push (`.github/workflows/ci.yml`).
